宿舍内通过PC摄像头的监控保护程序

2026-11-27 · 9 分钟阅读

摄像头人脸 / 移动监控程序 —— 项目介绍与说明书

本项目是一个基于 OpenCV 的本地摄像头监控程序。程序通过深度学习人脸检测（YuNet）与帧差法移动检测，在检测到人脸或有人经过/靠近时自动录制视频，并在画面内叠加实时时间戳水印；同时支持同步录音、抓拍人脸截图、触发异常报警、记录事件日志，并可一键生成 Excel 统计报表。程序提供可视化图形面板与命令行两种操作方式，核心依赖已随项目打包（libs/ 目录），开箱即用，无需额外配置环境。

本文档依次说明项目的功能概览、设计思路与技术选型、使用说明与常见问题，供使用者快速上手与二次开发参考。

正文

一、项目简介

1.1 功能概览

功能 说明
人脸检测 使用 OpenCV 的 YuNet 深度学习模型实时检测画面中的人脸，精度高、对角度与光照较鲁棒
移动检测 用帧差法检测画面变化，判断「有人经过 / 靠近」
自动录像 检测到人脸或明显移动即开始录制，画面内叠加实时时间戳水印；事件结束后自动停止
同步录音 可选开启，把麦克风声音录成与视频同名的 WAV 文件
人脸截图 录制事件开始时抓拍整帧，之后人脸出现期间按间隔抓拍，并单独裁剪人脸特写
异常报警 检测到人脸时发出提示音并显示红色报警边框（默认关闭，可开启）
事件日志 每次事件写入 events.csv，记录起止时间、时长、触发类型、人脸数等
Excel 报表 退出时自动生成 events.xlsx，含「事件明细」与「统计汇总」两个工作表
图形面板 提供 Tkinter 可视化面板，实时预览、开始/停止、参数调节、打开输出目录等

1.2 使用方式

  • 可视化面板：双击 run_gui.bat，无命令行窗口，适合日常使用。
  • 命令行：双击 run.bat 或运行 python monitor.py，适合后台静默、脚本化调度等场景。

二、设计思路

2.1 总体架构

程序采用「单进程 + 单线程主循环」的简洁架构，核心逻辑封装在 monitor.py 的 FaceMotionMonitor 类中：

  • 摄像头取流 → 每帧处理（检测 → 触发判定 → 状态机 → 录像/截图/报警 → 叠加水印） → 显示/写盘。
  • 图形界面 gui.py 通过调用同一套 process_frame() 方法复用全部核心逻辑，仅替换「显示」与「交互」部分，保证命令行版与 GUI 版行为一致。

2.2 双触发机制

程序采用人脸检测 + 移动检测双通道触发，互补覆盖「有人出现」的各种情况：

  1. 人脸检测（YuNet）：cv2.FaceDetectorYN 加载 ONNX 模型，对每帧做推理，返回人脸框与置信度。置信度高于阈值（默认 0.6）即判定为「有人脸」。选择 YuNet 是因为 OpenCV 5.x 已移除传统的 Haar 级联（CascadeClassifier），而 YuNet 精度更高、现代且持续维护。
  2. 移动检测（帧差法）：将灰度图缩放到 320×240 以降低算力，做高斯模糊 → 与上一帧 absdiff → 阈值二值化 → 膨胀去噪，统计变化像素占比作为「移动量」。
  3. 触发判定：默认「人脸 或 移动」任一满足即触发录制；开启 --face-only 后，仅人脸触发、忽略纯移动，用于「只录人」的场景。

设计用意：人经过/靠近时可能背对镜头、距离远或只有侧脸，人脸检测不一定命中；移动检测可兜底捕获「有人经过」，而人脸检测负责确认「是人」。两者互补，兼顾灵敏度与特异性。

2.3 录制状态机

录制采用「触发—顺延—停止」的三态状态机：

  • 触发：检测到触发条件且不在冷却期 → 开始录制，记录事件开始时间与触发类型，写入事件日志。
  • 顺延：录制期间再次检测到触发 → 更新「最后触发时刻」，延长录制。
  • 停止：无触发且距「最后触发时刻」超过 min-record-seconds（最短录制时长）→ 停止录制、释放资源、写日志。

冷却期 cooldown 用于把连续动作合并为一次事件，避免事件结束后立刻重复触发产生碎文件。

2.4 各功能设计要点

  • 时间戳水印：每帧在左上角绘制半透明黑条 + 时间 + 状态文字。由于 OpenCV 内置字体仅支持 ASCII，水印如 Monitoring (STANDBY)、[REC] trigger:face）。
  • 录音：使用 sounddevice（自带 PortAudio）后台采集麦克风，保存为与视频同名的独立 .wav 文件，不与视频合并。若检测不到麦克风，自动降级为「仅录像」并提示。
  • 人脸截图：事件开始时抓拍整帧；录制期间人脸持续出现时按 snapshot-interval 间隔抓拍整帧，并对每张人脸做加边裁剪，单独保存特写。
  • 异常报警：检测到人脸时发出蜂鸣提示音并绘制红色边框。蜂鸣在后台线程中播放，避免阻塞主循环导致画面卡顿；报警默认关闭，可通过 --alarm 开启。
  • 日志与报表：事件以 CSV 记录（UTF-8 with BOM， Excel 打开中文/时间）；report.py 使用 openpyxl 生成带格式的双工作表 Excel（事件明细 + 统计汇总）。
  • 可视化：选用标准库 Tkinter，无需额外安装依赖；用 Pillow 把 OpenCV 帧转成 PhotoImage 显示；用 pythonw.exe 启动以隐藏命令行窗口。

2.5 技术栈与依赖

组件 用途 版本
Python 运行环境 3.12
OpenCV (opencv-python) 取流、人脸检测、录像、图像处理 5.1.0
NumPy 数值计算 2.5.5
sounddevice 麦克风录音 0.5.6
openpyxl 生成 Excel 报表 3.1.5

依赖已安装在工作区 libs/ 目录，程序启动时自动将该目录加入模块搜索路径，实现自包含、免配置。

三、使用说明

3.1 环境要求

  • Windows 操作系统；
  • 一个 USB / 内置摄像头（录像、人脸、移动检测必需）；
  • 麦克风（仅当需要录音功能时必需）；
  • 依赖无需手动安装（若迁移环境，执行 pip install -r requirements.txt）。

3.2 目录结构

文件/目录 说明
monitor.py 主程序（命令行版核心）
gui.py 可视化面板
run_gui.bat 双击启动图形面板（推荐）
run.bat 双击启动命令行版
report.py / report.bat 生成 / 双击生成 Excel 报表
selftest.py 环境自检（无需摄像头）
requirements.txt 依赖清单
libs/ 已打包的依赖
models/face_detection_yunet_2023mar.onnx 人脸检测模型
recordings/ 视频与录音输出（按日期分文件夹）
snapshots/ 人脸截图输出（按日期分文件夹）
events.csv 事件日志
events.xlsx 自动生成的 Excel 报表

3.3 快速开始

方式一：可视化面板（推荐）

  1. 双击 run_gui.bat，弹出图形面板并自动开始监控。
  2. 面板上可直接：开始/停止、勾选「只录人脸 / 录音 / 报警 / 抓拍人脸」、调整阈值、打开录像/截图目录、生成 Excel 报表。
  3. 点「退出」关闭，退出时自动生成 events.xlsx。

方式二：命令行

run.bat                 :: 默认参数启动
run.bat --face-only     :: 只录人脸
run.bat --audio         :: 开启录音
run.bat --alarm         :: 开启报警
run.bat --no-preview    :: 后台静默运行（不显示预览）

3.4 参数参考

参数 默认值 含义
--camera 0 摄像头设备序号
--face-score 0.6 人脸置信度阈值（0~1），越小越灵敏
--face-only 关 只在检测到人脸时录像（忽略纯移动）
--motion-threshold 0.02 移动触发阈值（变化像素占比），越小越灵敏
--min-record-seconds 10 每次事件最短录制秒数
--cooldown 5 事件结束后的冷却秒数
--audio 关 是否同步录音（存为同名 WAV）
--snapshot 开 是否抓拍人脸截图
--snapshot-interval 3 人脸出现期间截图间隔(秒)
--alarm 关 人脸报警（提示音 + 红框）
--report 开 退出时自动生成 Excel 报表
--preview 开 是否显示实时预览窗口
--fps 20 录制帧率
--codec mp4v 视频编码（无法播放时可换 MJPG）

3.5 输出说明

  • 视频：recordings/YYYYMMDD/YYYYMMDD_HHMMSS_触发类型.mp4，画面左上角带时间戳水印。
  • 录音：开启 --audio 后，与视频同名保存为 .wav。
  • 截图：snapshots/YYYYMMDD/…_full.jpg（整帧）与 …_face0.jpg（人脸特写）。
  • 日志：events.csv，字段为开始/结束时间、时长、触发类型、是否报警、人脸数峰值、移动量峰值、截图数、录音文件名。
  • 报表：events.xlsx，含「事件明细」「统计汇总」两个工作表。

3.6 常见问题

问题 处理
提示「无法打开摄像头」 确认摄像头已连接、未被微信/浏览器/会议软件占用；尝试 --camera 1
开启录音但没有声音文件 确认有麦克风且系统允许应用访问；程序会提示「无法打开麦克风」，视频仍正常录制
误录太多（宠物/光线/窗帘） 调高 --motion-threshold（如 0.03），或使用 --face-only 只录人脸
漏录了人 调低 --motion-threshold（如 0.005）或调低 --face-score（如 0.5）
报警声音吵 / 卡顿 报警默认关闭；开启后蜂鸣在后台线程播放，不会卡画面；可 --no-alarm 关闭
录出的 mp4 无法播放 换编码：--codec MJPG
先确认环境是否正常 运行 python selftest.py，全部 PASS 即环境正常

本程序以「低门槛、自包含、双通道检测」为设计原则，兼顾日常监控的实用性与可维护性。默认配置即可满足「有人经过/靠近即录像并记录时间」的核心需求，进阶功能（录音、截图、报警、报表、图形面板）均可按需开关，适合家庭、办公室、门店等轻量安防与看护场景。若您拥有USB环形摄像头，我猜这会是一个更好的选择。
